# Every App Carries a Three-Entry `.gitignore`

An app's `.gitignore` covers exactly what the root one does not: the local Wrangler state
directory, the local secrets file, and the generated Cloudflare types. Three entries,
nothing else.

## Why

- **`.dev.vars` holds real secrets.** It is the local counterpart of
  `wrangler secret put`, and the only reason `.env.example` exists is so the file's shape
  can be committed without its values.
- **`worker-configuration.d.ts` is generated by `bunx wrangler types`** from the bindings
  in `wrangler.jsonc`. Committing it means every binding change produces a diff of
  machine output that reviewers scroll past, and a stale copy that shadows the real one.
- **Re-listing what the root already ignores is how a list rots.** The old template's
  `.gitignore` still carried `/.react-router` — a directory from a framework this repo
  left behind — alongside six entries the root file already covered.

## Pattern

```gitignore
# Bad: duplicates the root file and keeps a dead entry
/node_modules
/.cache
/.react-router
/.wrangler
/coverage
/build
/assets
.DS_Store
.dev.vars
worker-configuration.d.ts
tsconfig.tsbuildinfo
```

```gitignore
# Good: apps/<name>/.gitignore
# Artifacts the root .gitignore does not already cover.

# Folders
/.wrangler

# Files
.dev.vars
worker-configuration.d.ts
```

Because `worker-configuration.d.ts` is not committed, it must be generated before the
first type check:

```bash
cd apps/<name> && bun run cf:typegen
```

Run it again after every binding added to `wrangler.jsonc`.

## Rules

1. Write the three entries and the header comment; add a fourth only for an artifact this app alone produces
2. Never commit `.dev.vars`; commit `.env.example` with the same keys and empty values
3. Never commit `worker-configuration.d.ts`; run `bun run cf:typegen` after any binding change
4. Check the root `.gitignore` before adding an entry — if it is already there, leave it out
