# Study the References

Before building a screen or a part, look at the reference that does it best and write down the moment
to match, with a width and a reason ("GitHub's facet popover lists counts per value at 1440, so you see
what a filter will leave before you apply it").

| Building | Look at | For |
| --- | --- | --- |
| Shell, nav | shadcn sidebar-07, Catalyst, Kumo, Dub, Polar | Inset card, rail with peek, panel swap, cookie collapse |
| List, filters | GitHub Issues, Linear, Dub, shadcn tasks | Facets with counts, chips, density, bulk bar |
| Table cells | Stripe Apps, Geist | Typed cells, `—`, alignment |
| Detail | GitHub Projects pane, Linear, Polar, Sentry | URL sheet, `n / N`, properties, timeline |
| Metrics | shadcn dashboard, Polar, Stripe, Vercel, Sentry | Stat anatomy, comparison, hatched gaps, row sparklines |
| Saving, settings | Primer rules, Polar, Catalyst, Ghost | Explicit vs instant, split rows, danger zone |
| Editor | WordPress, Sanity, Payload, Ghost | Save timings, publish button state |
| Feedback | Geist, Primer | Toast copy, banners, confirm copy, empty types |
| Keyboard | Geist, GitHub, Linear, Cloudflare, the reader app | Palette rules, `?` sheet, scopes |

The round's notes and ~210 screenshots (named `<site>-<what>-<width>-<theme>.png`) are in the shared
notes folder's `app-research/`; read the matching notes file before re-studying a site.

Signed-out references cover most patterns. Linear, Vercel and Stripe dashboards need a sign-in; if the
user signs in through the browser pane, look but never change anything.

## Rules

1. Name the reference and the moment before building.
2. Compare side by side when done; if yours feels heavier or slower, it is.
