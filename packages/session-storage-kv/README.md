# @sdxc/session-storage-kv

A `remix/session` `SessionStorage` implementation backed by a Cloudflare Workers KV-like store.

## Overview

Remix ships cookie, filesystem, memory, Redis, and Memcache session stores, but none
for Cloudflare Workers KV. This package fills that gap: `KVSessionStorage` implements
`SessionStorage` by JSON-serializing session data under a configurable key prefix and
TTL, and validating the stored shape on read so a corrupted or foreign KV value falls
back to an empty session instead of throwing.

It depends on a small `KVStore` contract (`get`/`put`/`delete`/`list`) rather than
Cloudflare's `KVNamespace` type directly, so it works against the real KV binding in
production and against an in-memory fake in tests without any Workers runtime.

## Usage

### Basic Example

```typescript
import { KVSessionStorage } from "@sdxc/session-storage-kv";
import { session } from "remix/middleware/session";

let storage = new KVSessionStorage(env.KV, { prefix: "session:" });

let middleware = session({ secrets: [env.COOKIE_SESSION_SECRET] }, storage);
```

### Custom TTL

```typescript
let storage = new KVSessionStorage(env.KV, {
	prefix: "session:",
	ttlSeconds: 60 * 60 * 24 * 30, // 30 days
});
```

## API

### `KVSessionStorage`

A `SessionStorage` implementation that persists session data as JSON in a `KVStore`.

#### `new KVSessionStorage(kv: KVStore, options?: KVSessionStorage.Options)`

Creates a KV-backed session storage adapter.

**Parameters:**

- `kv`: The `KVStore` to persist sessions in (a Cloudflare `KVNamespace` satisfies this).
- `options.prefix?`: Prefix prepended to every KV key (default `"session:"`).
- `options.ttlSeconds?`: KV expiration, either a number of seconds or a `@sdxc/duration` string such as `"30 days"` (default one year).

#### `storage.read(cookie: string | null): Promise<Session>`

Restores a session from its cookie id. Returns an empty session when the cookie is
`null`, the KV entry is missing, or the stored value fails shape validation.

#### `storage.save(session: Session): Promise<string | null>`

Persists, rotates, or destroys the session in KV depending on its dirty/destroyed
state, returning the session id to set as the cookie value (or `""` when destroyed,
or `null` when nothing changed).

### Types

#### `KVStore`

```typescript
interface KVStore {
	get(key: string): Promise<string | null>;
	put(
		key: string,
		value: string | ArrayBuffer | ReadableStream | ArrayBufferView,
		options?: { expirationTtl?: number },
	): Promise<void>;
	delete(key: string): Promise<void>;
	list(): Promise<{ keys: Array<{ name: string }> }>;
}
```

## Tips

1. Session ids are generated by `remix/session`; this package only persists the
   serialized `(data, flashData)` tuple under `${prefix}${sessionId}`.
2. A KV read that fails shape validation (not a 2-tuple of plain objects) is treated
   as a cache miss rather than an error, so a stale or foreign value never crashes a
   request — the visitor just gets a fresh session.
